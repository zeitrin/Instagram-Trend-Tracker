# T-shirt Trends

Прототип системы поиска трендов в дизайнах графических футболок по Instagram.

Скрипты собирают посты брендов футболок и стритвира и находят «выстрелившие» посты, то есть те, что набрали заметно больше обычного для своего аккаунта. Локальная vision-модель разбирает принты на этих постах: тема, стиль, мотивы, надпись. Затем считается, какие из них растут, и всё сводится в HTML-отчёт.

## Как это работает

```
Apify (сбор постов) → PostgreSQL → поиск выбросов → Ollama (разбор картинок) → расчет трендов → report.html
```

1. **Сбор** (`src/collect.py`): через Apify Instagram Scraper собираются последние посты аккаунтов из `config.py`, картинки скачиваются локально.
2. **Выбросы** (`src/analyze.py`): для каждого аккаунта считается медианная вовлечённость (`likes + 3 × comments`). Пост считается выбросом, если набрал в `LIFT_THRESHOLD` раз больше медианы своего аккаунта.
3. **Разбор картинок** (`src/analyze.py`): vision-модель в Ollama определяет по каждому выбросу:
   - есть ли на фото футболка с принтом;
   - надпись на принте;
   - тему (мемы, аниме, черепа, авто, …);
   - стиль (винтаж, минимализм, Y2K, …);
   - до 3 мотивов (`angel wings`, `spider web`, …).
4. **Тренды** (`src/report.py`): сравнивается **доля** каждой темы, стиля и мотива среди выбросов за последние `RECENT_DAYS` дней и за более ранний период. Растущим считается признак, чья доля выросла, если он встречается минимум у 2 разных аккаунтов.
5. **Отчёт** (`report.html`): растущие мотивы и темы с примерами, доли тем и стилей, надписи с принтов, галерея топовых постов. Картинки встроены в файл, отчёт можно пересылать одним файлом.

## Структура

```
instscrapper/
├── main.py            # точка входа
├── requirements.txt
├── README.md
└── src/
    ├── config.py      # все настройки: аккаунты, пороги, БД, прокси, модель
    ├── db.py          # подключение к PostgreSQL и схема таблиц
    ├── collect.py     # этап 1: сбор постов и скачивание картинок
    ├── analyze.py     # этап 2: поиск выбросов и разбор картинок моделью
    └── report.py      # этап 3: расчёт трендов и генерация отчёта
```

Таблицы в БД:
- `posts`: посты (аккаунт, дата, лайки, комментарии, просмотры, тип, подпись, путь к картинке);
- `tags`: результат разбора выбросов моделью.

## Требования

- Python 3.10+
- Docker Desktop (для PostgreSQL)
- [Ollama](https://ollama.com)
- Аккаунт [Apify](https://apify.com) (на старте хватает бесплатных кредитов)
- Видеокарта с 8+ ГБ видеопамяти желательна. На CPU всё работает, но разбор картинок идёт медленно.

## Установка

**1. База данных**

```
docker run -d --name trends-db -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=trends -p 5433:5432 pgvector/pgvector:pg16
```

Используется порт `5433`, чтобы не конфликтовать с локально установленным PostgreSQL.

**2. Модель**

```
ollama pull qwen2.5vl:7b
```

Для видеокарт с памятью меньше 8 ГБ: `ollama pull qwen2.5vl:3b`, и поменяйте `OLLAMA_MODEL` в `src/config.py`.

**3. Зависимости**

```
pip install -r requirements.txt
```

**4. Токен Apify**

Токен читается из переменной окружения. В коде его хранить не нужно.

Windows:
```
setx APIFY_TOKEN "ваш_токен"
```

Linux / macOS:
```
export APIFY_TOKEN="ваш_токен"
```

После `setx` откройте новый терминал.

**5. Прокси (если Instagram недоступен напрямую)**

Картинки скачиваются с CDN Instagram. Если он заблокирован, укажите в `src/config.py` локальный прокси VPN-клиента:

```
PROXY = "socks5h://127.0.0.1:10808"
```

Если доступ прямой, поставьте `PROXY = None`.

## Запуск

Все этапы по порядку:
```
python main.py
```

Отдельные этапы:
```
python main.py collect          # сбор постов и картинок
python main.py analyze          # поиск выбросов и разбор моделью
python main.py report           # расчёт трендов и отчёт
python main.py analyze report   # несколько этапов подряд
```

Запускать нужно из корня проекта. Этап `report` откроет `report.html` в браузере.

Этап `analyze` можно прервать и запустить снова: уже разобранные посты пропускаются.

## Настройки

Всё задаётся в `src/config.py`:

| Параметр | По умолчанию | Описание |
|---|---|---|
| `ACCOUNTS` | 15 брендов | аккаунты для мониторинга (без `@`) | по умолчанию пустой |
| `POSTS_PER_ACCOUNT` | 40 | сколько последних постов собирать с аккаунта |
| `LIFT_THRESHOLD` | 2.0 | во сколько раз выше медианы пост должен набрать, чтобы считаться выбросом |
| `MAX_OUTLIERS` | 100 | сколько выбросов максимум отдавать модели за запуск |
| `RECENT_DAYS` | 28 | граница между периодами «сейчас» и «раньше» |
| `OLLAMA_MODEL` | `qwen2.5vl:7b` | vision-модель для разбора картинок |

Подсказки:
- выбросов слишком много: поднимите `LIFT_THRESHOLD` до 2.5–3;
- отчёт пишет, что сравнивать не с чем: увеличьте `POSTS_PER_ACCOUNT` или уменьшите `RECENT_DAYS`.

## Полезные SQL-запросы

Сколько постов собрано по аккаунтам:
```sql
SELECT account, COUNT(*) FROM posts GROUP BY account ORDER BY 2 DESC;
```

Результаты разбора:
```sql
SELECT p.account, t.lift, t.theme, t.style, t.motifs, t.print_text
FROM tags t JOIN posts p USING (shortcode)
WHERE t.is_tshirt
ORDER BY t.lift DESC;
```

Очистить данные:
```sql
TRUNCATE tags, posts;
```

## Ограничения прототипа

- Тренд считается по одному сбору: свежие посты сравниваются со старыми. Для надёжных выводов нужен ежедневный сбор и история снимков.
- Просмотры есть только у видео и Reels. Основная метрика — лайки и комментарии.
- Часть выбросов — не футболки (лукбуки, анонсы). Они отсеиваются моделью и в тренды не попадают.
- Мотивы — свободные теги модели, похожие формулировки (`angel wing` / `angel wings`) пока не объединяются.
